1. Executive Summary

ENRG is a DePIN-native energy protocol that turns real-world energy production into a programmable, on-chain asset. Each SRC token represents 1 MWh of verifiable energy, backed by cryptographic proofs from IoT devices (ESP32, industrial Modbus/RS485 meters) and decentralized oracles.

2. The Problem – Centralized Energy Markets

Today's energy markets are dominated by centralized utilities, opaque intermediaries, and fragmented data silos. Small producers cannot monetize surplus, consumers face opaque pricing, and renewable energy lacks transparent verification.

3. Our Solution – Proof-of-Production (PoP)

ENRG introduces Proof-of-Production: a cryptographic pipeline that connects physical energy devices to on-chain tokens.

Industrial Integration: Supports Modbus RTU/RS485 meters (Schneider, Siemens, ABB, Меркурий, Энергомера) via gateway firmware that translates readings into signed proofs.

Anti-Fraud System

  • Hardware security: ATECC608 Secure Element for key storage and signing.
  • Replay protection: Monotonic nonce per device + timestamp validation (MAX_PROOF_AGE = 1 hour).
  • Physical limits: max_power_w per device, time-based limits (10 min intervals).
  • Multi-oracle verification: Switchboard aggregates data from multiple oracles (planned).
  • Anomaly detection: Monitoring sudden spikes, comparison with historical data via Energy Reputation Score (ERS).
  • Tamper detection: Enclosure sensors → key revocation.

6. Emission Curve & Scarcity Forecast

Base formula: E(S) = 1 MWh × k^S, where S is the fraction of already mined tokens, and k is the difficulty coefficient.

  • Conservative (5% network growth/year): SRC reaches structural scarcity by 2035.
  • Moderate (15% growth/year): Scarcity by 2032.
  • Aggressive (10x first year): Scarcity by 2029.

In all scenarios, SRC becomes structurally deflationary as network adoption grows. The model is asymptotic — the last token is practically unattainable.

7. Energy Vault – The Economic Engine

Every MWh Minted Feeds the Vault. Every Fee Feeds Scarcity. The Vault accumulates protocol fees, executes buyback & burn, and distributes to stakers, DAO, and emergency fund.

  • Buyback & Burn (20% of fees): Constant deflationary pressure. Tokens are burned via buyback_and_burn instruction.
  • Staking Pool (40%): Rewards distributed proportionally to staked share.
  • DAO Treasury (30%): Community-governed development fund.
  • Emergency Fund (10%): Protocol insurance and black swan protection.

8. Smart Contract Architecture

Modular Solana programs written in Rust using Anchor Framework 1.0.3:

  • enrg-mvp: Core protocol — minting, proof verification (Ed25519 via sysvar), vault, staking, buyback & burn, vesting, device lifecycle.
  • enrg-profile: Device profiles — rated power, metadata, 30-day rolling energy window. Accessed via CPI using declare_program!.

All programs auditable and upgradeable via DAO governance. Interaction between programs occurs via CPI (Cross-Program Invocation).

9. IoT Hardware Prototype

  • Consumer: ESP32 + PZEM-004T, Ed25519 signing, Wi-Fi, OLED display.
  • Industrial: Modbus/RS485 gateway (ESP32 + RS485 shield) supporting Schneider, Siemens, ABB, Меркурий, Энергомера.
  • Secure Element: ATECC608 planned for production — private key never leaves the device.

10. Oracle Architecture

  • Current (MVP): Node.js oracle server with Express, deployable on Render, Railway, or any PaaS. Verifies Ed25519 signatures, validates nonce + timestamp, aggregates data into pools.
  • Future: Switchboard decentralized oracle network for redundant verification and fault tolerance.
  • API Endpoints: POST /api/v1/proof/submit, GET /api/v1/device/{id}/status, GET /api/v1/pool/{id}/stats.
