Technical Overview

Deep-dive into the ENRG Protocol architecture, on-chain programs, account structure, oracle flow, and API reference.

Architecture

The system consists of four layers:

Frontend

Static HTML/JS (Phantom wallet, modular JS)

↓
Oracle API

REST API — device telemetry, signed mint requests

↓
Solana Programs

enrg-mvp · enrg-profile · SPL Token (CPI)

↓
State

On-chain PDAs — profiles, devices, mint records

On-Chain Programs

enrg-mvp

Core program responsible for:

  • Verifying oracle Ed25519 signatures
  • Minting SRC tokens via CPI to SPL Token program
  • Enforcing mint constraints (max supply, device status)

enrg-profile

Profile and device registry:

  • Participant profiles (PDA per wallet)
  • Device registration (PDA per device)
  • Device status management (active / inactive)

Account Structure

Profile PDA

seeds: ["profile", wallet_pubkey]

{
  wallet:    Pubkey,
  name:      String (64),
  email:     String (128),
  country:   String (64),
  created_at: i64,
  bump:      u8,
}

Device PDA

seeds: ["device", wallet_pubkey, device_id]

{
  owner:     Pubkey,
  device_id: String (32),
  name:      String (64),
  device_type: String (32),
  capacity:  f64,
  location:  String (128),
  status:    DeviceStatus,  // Active | Inactive
  created_at: i64,
  bump:      u8,
}

Oracle Flow

  1. Device sends telemetry to Oracle API (POST /telemetry)
  2. Oracle validates device PDA status on-chain
  3. Oracle aggregates kWh readings over 1h window
  4. Oracle signs payload: { deviceId, walletAddress, amount_mwh, timestamp } with Ed25519 key
  5. Oracle submits mint_src instruction with signature proof
  6. On-chain program verifies signature via Instructions sysvar
  7. SPL Token minted to device owner's ATA
The oracle's Ed25519 public key is hardcoded into the enrg-mvp program at deploy time. Changing it requires a program upgrade.

Security

  • Ed25519 verification — all mint requests require a valid oracle signature checked on-chain
  • PDA ownership checks — all instructions verify signer matches the PDA owner
  • Max supply enforcement — program rejects mints that would exceed 1B SRC
  • Wallet-based auth — frontend uses signMessage for session authentication; no passwords stored
  • Session TTL — auth sessions expire after 24 hours
  • No localStorage secrets — sensitive data stored in sessionStorage only

Frontend Module Structure

js/
├── config.js      — network, program IDs, constants
├── wallet.js      — Phantom adapter, signMessage
├── api.js         — Oracle REST calls
├── auth.js        — wallet-based session
├── ui.js          — toast, formatters, render helpers
├── main.js        — index.html entry point
├── dashboard.js   — dashboard logic
└── register.js    — device registration flow

All modules are ES modules loaded with type="module". No build step required for development. For production, bundle with Vite or esbuild.
